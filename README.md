# slavda_bottle — прототип отбраковки (без бюджета)

Максимально урезанный прототип к КП «пилот системы видеоконтроля на линии розлива».
Цель — проверить **механику отбраковки** до закупки оборудования: найдёт ли классическое
зрение брак, не будет ли сбрасывать годное и сбросит ли сбрасыватель именно ту бутылку.

Не нужны промышленные камеры, тоннель, GPU, энкодер, пневматика, БД и сервер.
Нужен ноутбук на Python; для живых снимков — веб-камера или телефон.

## Что есть, а чего нет по сравнению с КП

| В КП | В прототипе |
|---|---|
| Нет крышки, цвет крышки (ΔE Lab), уровень налива, наличие/перекос/смещение этикетки | **Есть**, классическое зрение, одна боковая камера |
| Дефекты поверхности этикетки (PatchCore/EfficientAD), недопечать, OCR | Нет (приоритет 2) |
| 5–6 камер, световой тоннель, импульсная подсветка | 1 камера, фон и свет подручные |
| Энкодер, фотодатчики, пневмосбрасыватель | Программная модель: очередь по энкодеру, датчик у сбрасывателя, fail-safe |
| Рецепты SKU, переключение без программиста | JSON-рецепт в мм + `calibrate` по годным бутылкам |
| Режим «тени» | `--shadow`: решает и пишет в журнал, не сбрасывает |
| Дашборд, архив снимков, отметка «ложная отбраковка» | Страница на стандартной библиотеке Python, CSV и JPEG в папке |
| Критерии приёмки | `evaluate` считает пропуск брака по классам и ложную отбраковку против целей КП |
| PostgreSQL, MinIO, FastAPI, Docker, ONNX/TensorRT | Нет |

## Быстрый старт (без камеры, на синтетике)

```bash
pip install -r requirements.txt

# 1. Годные бутылки -> эталоны рецепта (цвет крышки и этикетки, номинал уровня, масштаб)
python -m bottlecheck synth --out data/good --n 60 --defect-rate 0 --seed 1
python -m bottlecheck calibrate --recipe recipes/demo_05.json --images data/good --out recipes/demo_05.json

# 2. Поток с 30% брака семи видов -> инспекция -> журнал и снимки брака
python -m bottlecheck synth --out data/test --n 800 --seed 7
python -m bottlecheck run --recipe recipes/demo_05.json --source data/test --out out

# 3. Метрики приёмки против целей из КП
python -m bottlecheck evaluate --journal out/journal.csv --labels data/test/labels.csv

# 4. Дашборд: снимки брака с причиной, кнопки «брак подтверждён / ложная отбраковка / пропущен брак»
python -m bottlecheck review --out out          # http://127.0.0.1:8000/

# 5. Конвейер: доедет ли решение до нужной бутылки
python -m bottlecheck simulate --journal out/journal.csv
```

Результат на синтетике (800 бутылок, 261 бракованная): пропуск брака 0% по всем классам,
ложная отбраковка 0%. Синтетика нужна, чтобы проверить логику, а не качество: на настоящих
бутылках цифры будут хуже, и именно их нужно получить на следующем шаге.

## Живые бутылки за ноль рублей

- **Камера:** веб-камера ноутбука или телефон как веб-камера (DroidCam, Iriun, Camo).
- **Свет и фон:** бутылка между камерой и равномерно светлым фоном. Подойдёт экран планшета
  или монитора с белой картинкой на полной яркости (задний свет для уровня), а сбоку —
  настольная лампа через лист бумаги. Свет и положение камеры зафиксировать, чтобы они не менялись.
- **Позиционирование:** бутылка боком к камере, целиком в кадре, у края кадра стоит фон.
  Масштаб программа определяет по ширине бутылки, поэтому расстояние подбирать точно не нужно.

```bash
# эталоны с 20–50 годных бутылок (каждую чуть повернуть вокруг оси)
python -m bottlecheck run --recipe recipes/demo_05.json --source cam:0 --out out_good --shadow
python -m bottlecheck calibrate --recipe recipes/demo_05.json --images out_good/snapshots --out recipes/my_sku.json
```

Для калибровки удобнее сохранять сырые кадры. Можно отснять серию телефоном и положить
файлы в папку: `--source` принимает папку с `.jpg` или `.png`.

Режим камеры работает как «виртуальный фотодатчик»: съёмка срабатывает, когда бутылка
встаёт по центру кадра. Чтобы взвести датчик снова, бутылку нужно убрать из кадра.
Пробел — ручной триггер, `q` — выход. Нужен `opencv-python` с GUI, вариант headless не подойдёт.

Рецепт: все зоны в мм от дна (`recipes/demo_05.json`). Для своей бутылки нужно поправить
`bottle` (диаметр и высоту с крышкой), зоны `cap` и `label`, зону поиска уровня и допуски.
Затем запустить `calibrate`: он снимет эталоны и покажет разброс годных, по которому
выставляются пороги.

## Как устроены проверки (`bottlecheck/vision.py`)

- **Поиск бутылки:** отличие от цвета фона (медиана по рамке кадра), крупнейшая область.
  Масштаб px/мм берётся из ширины бутылки с поправкой на размытие края `edge_px`;
  поправку находит `calibrate`.
- **Крышка:** доля «непрозрачных» пикселей в зоне крышки, затем медианный цвет в Lab
  и ΔE до эталона.
- **Уровень:** профиль яркости в узкой полосе по оси горла. Мениск — самый сильный
  переход «темно снизу → светло сверху». Если перехода нет, это `level_not_found`, и бутылка
  тоже идёт в брак.
- **Этикетка:** маска по ΔE до цвета этикетки. По покрытию проверяется наличие,
  по наклону верхнего и нижнего краёв — перекос, по центру — смещение в мм.
- Если датчик сработал, а бутылки в кадре нет (`no_bottle`), бутылка тоже сбрасывается.

## Механика сброса (`bottlecheck/tracking.py`)

Между камерой и сбрасывателем едут несколько бутылок, поэтому решение «сбросить следующую»
неверно. Каждое решение ставится в очередь с позицией энкодера *на момент съёмки* плюс
расстояние до сбрасывателя. Датчик перед сбрасывателем сверяет, совпала ли позиция
в пределах окна:

- бутылку сняли с ленты: запись протухает, тревога `lost_bottle`, следующие решения не сдвигаются;
- приехала незнакомая бутылка (подставили, решение опоздало, бутылка проскользнула):
  тревога `unknown_bottle` и сброс (fail-safe);
- в режиме «тени» сброс не срабатывает никогда, решения только пишутся в журнал.

`simulate` прогоняет эти сценарии и показывает, чего они стоят:

```bash
python -m bottlecheck simulate --p-remove 0.01 --p-foreign 0.005   # люди трогают бутылки
python -m bottlecheck simulate --latency-ms 3000                    # решение опаздывает: всё в сброс
python -m bottlecheck simulate --slip-mm 15                         # проскальзывание больше окна
```

Отсюда требования к железу пилота: минимальное расстояние от камеры до сбрасывателя
(больше, чем скорость × время решения) и окно совпадения (больше проскальзывания тары).

## Что дальше

1. Снять 50–100 годных и по 10–30 бракованных бутылок каждого класса на реальной таре
   (брак можно сделать руками: открутить крышку, отлить, сдвинуть этикетку),

2. Если метрики сходятся, имеет смысл этап 0 из КП. Если нет — станет ясно, какой класс
   дефектов упирается в свет или оптику, ещё до закупки.

## Структура

```
bottlecheck/
  vision.py       поиск бутылки и проверки
  inspection.py   решение «годно / брак + причины», аннотация снимка
  pipeline.py     источники кадров (папка, камера), журнал, архив снимков
  tracking.py     очередь по энкодеру, сбрасыватель, симуляция конвейера
  calibrate.py    эталоны рецепта по годным бутылкам
  evaluate.py     метрики приёмки из КП
  review.py       дашборд и отметки оператора
  synth.py        синтетические бутылки с дефектами
recipes/demo_05.json
tests/
```

Тесты: `python -m pytest`.
